# 법령정보 MCP 서버 오프라인 설치 가이드 (RHEL 9.6)

인터넷이 막힌 Red Hat Enterprise Linux 9.6 서버에 법령정보 MCP 서버(`get_lawfulltext`)를 컨테이너로 올리고, 리버스 프록시에서 `/getlawtext/mcp` → `127.0.0.1:8087/mcp`로 연결하는 방법입니다.

```
MCP 클라이언트 ──HTTPS──▶ 리버스 프록시 (/getlawtext/mcp)
                              │
                              ▼
                      127.0.0.1:8087/mcp  ── 컨테이너 getlawtext
                                                   │
                                                   ▼ HTTPS (나가는 연결)
                                          www.law.go.kr (법제처 Open API)
```

## 0. 준비물

| 파일 (dist 폴더) | 용도 |
|---|---|
| `getlawtext_1.0_amd64.tar` | 컨테이너 이미지 (`localhost/getlawtext:1.0`, linux/amd64) |
| `getlawtext_1.0_amd64.tar.sha256` | 무결성 확인용 체크섬 |
| `getlawtext.env` | 환경설정 템플릿 (인증키·접속 키) |
| `getlawtext.container` | Podman Quadlet(systemd) 서비스 정의 |
| `nginx-getlawtext.conf`, `getlawtext-proxy.inc` | nginx 리버스 프록시 설정 |
| `httpd-getlawtext.conf` | Apache httpd 리버스 프록시 설정 |

서버 조건

- RHEL 9.6 x86_64, `podman` 설치 (RHEL 기본 패키지, `rpm -q podman`으로 확인)
- 서버 → `www.law.go.kr:443` 나가는 연결. **"오프라인"이어도 이 연결은 반드시 필요합니다.** 직접 열 수 없으면 사내 HTTP 프록시를 통하도록 `HTTPS_PROXY`를 설정합니다(3단계).
- 법제처 Open API 인증키(OC). open.law.go.kr에서 신청할 때 **이 서버가 인터넷으로 나갈 때 쓰는 공인 IP**를 등록해야 합니다. 등록하지 않으면 API가 HTML 안내문을 돌려주고, 도구는 `[오류] API가 JSON이 아닌 응답을 반환했습니다`를 표시합니다.

## 1. 이미지 옮기기와 확인

dist 폴더를 USB나 내부 파일 전송으로 서버의 `/opt/getlawtext/`에 복사합니다.

```bash
cd /opt/getlawtext
tr -d '\r' < getlawtext_1.0_amd64.tar.sha256 | sha256sum -c -   # "OK" 가 나와야 함 (Windows 줄바꿈 제거 후 확인)
```

## 2. 이미지 불러오기

```bash
sudo podman load -i getlawtext_1.0_amd64.tar
sudo podman images localhost/getlawtext          # TAG 1.0 이 보이면 정상
sudo podman run --rm --entrypoint cat localhost/getlawtext:1.0 /etc/redhat-release   # Red Hat Enterprise Linux release 9.6
```

Docker를 쓰는 서버라면 `sudo docker load -i getlawtext_1.0_amd64.tar`를 실행합니다. 이후 단계의 `podman`을 `docker`로 바꾸면 됩니다(Quadlet 대신 6장의 `docker run` 사용).

## 3. 환경설정 파일 작성

```bash
sudo mkdir -p /etc/getlawtext
sudo cp getlawtext.env /etc/getlawtext/
sudo chmod 600 /etc/getlawtext/getlawtext.env
openssl rand -hex 32                                  # MCP 접속 키 생성 (출력값을 복사)
sudo vi /etc/getlawtext/getlawtext.env
```

| 항목 | 값 |
|---|---|
| `LAW_OC` | 법제처 Open API 인증키 (필수) |
| `MCP_API_KEY` | 위에서 만든 접속 키. 사용자별로 나누려면 `키1,키2` |
| `MCP_ALLOWED_HOSTS` | 프록시의 외부 도메인(예: `law.example.go.kr`). 비우면 Host 검사 안 함 |
| `HTTPS_PROXY` | law.go.kr로 직접 나갈 수 없을 때 사내 프록시 주소 |

`MCP_ALLOWED_HOSTS`를 넣을 때는 프록시가 서버로 넘기는 `Host` 값과 정확히 같아야 합니다. 이 가이드의 nginx·httpd 설정은 클라이언트가 접속한 도메인을 포트 없이 넘깁니다. 값이 맞지 않으면 `421 Invalid Host header`가 납니다.

## 4. 서비스 등록 (Podman Quadlet)

```bash
sudo cp getlawtext.container /etc/containers/systemd/
sudo systemctl daemon-reload
sudo systemctl start getlawtext
sudo systemctl status getlawtext --no-pager
```

- Quadlet 서비스는 `[Install]` 설정으로 부팅 시 자동 시작됩니다. `systemctl enable`은 하지 않아도 됩니다(Quadlet이 만든 유닛이라 enable 명령은 오류가 납니다).
- 로그: `sudo journalctl -u getlawtext -f`
- 시작 로그에 `MCP 접속 키 인증 사용 (키 N개)`가 보이면 키가 적용된 것입니다.

## 5. 동작 확인 (서버 안에서)

```bash
# 상태 (접속 키 없이 응답)
curl -s http://127.0.0.1:8087/health
# → {"status":"ok","server":"getlawtext","law_oc_set":true}

# MCP 초기화 (접속 키 필요)
KEY='<MCP_API_KEY 값>'
curl -s -X POST http://127.0.0.1:8087/mcp \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}'
# → event: message / data: {"jsonrpc":"2.0","id":1,"result":{...}}  이면 정상

# law.go.kr 연결 확인 (컨테이너 안에서)
sudo podman exec getlawtext python3.12 -c "import urllib.request;print(urllib.request.urlopen('https://www.law.go.kr',timeout=10).status)"
# → 200 이면 정상. 시간 초과면 방화벽 또는 HTTPS_PROXY 확인
```

## 6. (Docker 사용 시) 서비스 실행

```bash
sudo docker run -d --name getlawtext --restart unless-stopped \
  -p 127.0.0.1:8087:8087 \
  --env-file /etc/getlawtext/getlawtext.env \
  --read-only --security-opt no-new-privileges --cap-drop ALL \
  localhost/getlawtext:1.0
```

## 7. 리버스 프록시 설정

외부 `/getlawtext/mcp` 요청을 내부 `http://127.0.0.1:8087/mcp`로 넘깁니다. MCP는 응답을 스트리밍(SSE)으로 보내므로 **프록시 버퍼링을 꺼야** 하고, 연결을 오래 유지하도록 타임아웃을 늘려야 합니다. 아래 두 설정 모두 테스트 환경에서 초기화, 도구 목록, 도구 호출, 스트리밍(GET) 채널, 접속 키 검사, 끝에 `/`가 붙은 요청까지 확인했습니다.

### nginx

```bash
sudo cp getlawtext-proxy.inc /etc/nginx/
sudo cp nginx-getlawtext.conf /etc/nginx/conf.d/getlawtext.conf
# 이미 쓰는 server { } 가 있으면 conf 파일의 location 두 줄만 그 안에 넣고 upstream 블록은 http 수준에 둡니다.
sudo nginx -t && sudo systemctl reload nginx
```

### Apache httpd

```bash
sudo cp httpd-getlawtext.conf /etc/httpd/conf.d/getlawtext.conf
sudo apachectl configtest && sudo systemctl reload httpd
```

`ProxyPassMatch`는 대상 주소에 `$1` 같은 역참조가 없으면 원래 경로를 뒤에 덧붙입니다(`/mcp/getlawtext/mcp`로 전달되어 404). 제공한 설정은 캡처 그룹을 써서 이 문제를 피합니다. 직접 고칠 때 이 부분을 바꾸지 마세요.

### SELinux (프록시와 같은 서버일 때)

RHEL은 기본으로 웹 서버가 임의 포트(8087)에 연결하지 못하게 막습니다. 프록시에서 `502 Bad Gateway`가 나고 `/var/log/audit/audit.log`에 `denied { name_connect }`가 보이면 둘 중 하나를 실행합니다.

```bash
sudo semanage port -a -t http_port_t -p tcp 8087        # 8087 포트만 허용 (권장)
# 또는
sudo setsebool -P httpd_can_network_connect 1           # 모든 포트 연결 허용
```

### 프록시가 다른 서버일 때

- Quadlet의 `PublishPort=127.0.0.1:8087:8087`을 `PublishPort=8087:8087`로 바꾸고 프록시 설정의 `127.0.0.1`을 MCP 서버 IP로 바꿉니다.
- 방화벽은 프록시 서버 IP에서 오는 8087만 엽니다.

```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<프록시IP>/32" port port="8087" protocol="tcp" accept'
sudo firewall-cmd --reload
```

### 프록시 경유 확인

```bash
curl -s -X POST https://<외부도메인>/getlawtext/mcp \
  -H "Authorization: Bearer $KEY" \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}'
```

## 9. 운영

| 작업 | 명령 |
|---|---|
| 재시작 | `sudo systemctl restart getlawtext` |
| 접속 키·인증키 변경 | env 파일 수정 후 재시작 |
| 로그 | `sudo journalctl -u getlawtext --since today` |
| 상태 | `sudo podman ps --filter name=getlawtext` (STATUS에 `healthy`) |
| 새 버전 반영 | 새 tar를 `podman load` → `.container`의 `Image=` 태그 변경 → `daemon-reload` → `restart` |
| 이전 버전 정리 | `sudo podman image prune` |

## 10. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| `401 unauthorized` | 접속 키가 없거나 틀림. 헤더 이름·`Bearer ` 띄어쓰기 확인 |
| `421 Invalid Host header` | `MCP_ALLOWED_HOSTS`가 프록시가 넘기는 Host 값과 다름. 값을 맞추거나 비움 |
| 프록시에서 `502` | 컨테이너 미기동(`systemctl status`) 또는 SELinux(7장) |
| 프록시에서 `404` | location 경로 오타, 또는 httpd에서 `ProxyPassMatch` 역참조 누락 |
| 응답이 끝까지 안 오거나 늦게 한꺼번에 옴 | 프록시 버퍼링이 켜져 있음. nginx `proxy_buffering off`, httpd `flushpackets=on` 확인 |
| `[오류] API가 JSON이 아닌 응답` | open.law.go.kr에 서버 공인 IP 미등록, 또는 OC 값 오류 |
| `[오류] ... ConnectTimeout` | law.go.kr 나가는 연결 차단. 방화벽 또는 `HTTPS_PROXY` 설정 |
| `'…' 에 해당하는 법령·행정규칙 검색 결과가 없습니다` | 이름 오타. 정확한 이름을 모르면 일부만 넣어 후보 목록을 받은 뒤 `mst`/`admrul_id`로 호출 |
